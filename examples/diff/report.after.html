API レート制限の設計メモ

作成: 設計エージェント / 2026-10-01

1. 背景

一部の顧客が短時間に大量のリクエストを送り、他の顧客の応答が遅くなる事象が起きている。 API 全体にレート制限を入れて、特定の顧客が資源を占有しないようにする。

2. 方式

トークンバケット方式を採用する。顧客ごとにバケットを持ち、リクエストごとにトークンを 1 つ消費する。

プラン上限（毎分）
Free60
Pro1,200
Enterprise個別に設定

3. 留意点

  • レート制限のカウンタは Redis に置き、全サーバーで共有する。
  • 上限を超えたリクエストには 429 を返し、Retry-After ヘッダで再試行までの秒数を伝える。
if bucket.tokens == 0:
    return Response(status=429, headers={"Retry-After": bucket.wait_seconds()})
bucket.tokens -= 1

4. 今後

1 か月分のアクセスログから、プランごとの上限値の妥当性を見直す。
