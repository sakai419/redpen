# redpen

ローカルの **Markdown / HTML をブラウザで読んで、選択箇所にコメントを付け、
引用とコメントだけの Markdown として書き出す** Chrome 拡張。

AI が生成したレポートや設計文書をレビューし、指摘をそのまま次の指示に貼り込むための道具です。

```
┌────────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│ AI がレポートを生成│ ───► │ redpen で赤入れ  │ ───► │ 指摘を貼って指示 │
│  report.md         │      │ 選択 → コメント  │      │ 直し方は自分で書く│
└────────────────────┘      └──────────────────┘      └──────────────────┘
```

## 設計方針

**書き出すのは「どこ」と「何を言ったか」だけ。** 表題・日時・件数・依頼文といった枠は付けません。
「この指摘を全部直して」なのか「1 番だけ検討して」なのかはユーザーが決めることで、
拡張が代わりに決めるものではないからです。引用も選択範囲の全文ではなく、
場所が特定できる長さ（40 文字）に切り詰めます。

出力はこれだけです。

```markdown
## L30 — 3. 提案する仕様 > 3.2 前提条件

> 本システムは常時オンラインであることを前提とする。

オフライン時の挙動が未定義。ネットワーク断で処理が落ちた場合の扱いを追記してください。

## L36 — 3. 提案する仕様 > 3.2 前提条件

> db.insert(row)

ロールバック無しは受け入れられません。トランザクション内で一括投入してください。
```

## 既存のハイライタと何が違うか

ハイライト＋コメント＋Markdown 書き出しができる拡張は既にいくつもあります
（Web Highlights、Annotate Website、Glasp、Hypothesis など）。redpen が違うのは 2 点です。

1. **原文の行番号が出る。**
   Markdown をレンダリングするとき、markdown-it が持っているブロックの原文行範囲
   (`token.map`) を `data-rp-line` として DOM に焼き込んでいます。だから
   「レンダリング後に選択した箇所」から「原文の何行目か」を復元できます。
   汎用ハイライタはレンダリング後の DOM しか見ないので、原理的にこれができません。

2. **出力が「リサーチノート」ではない。**
   既存ツールの書き出しは引用とメモを集める形式です。redpen は位置・引用・コメントが
   1 件ずつ揃った、そのまま貼れる形で出します。

さらに、指摘した引用箇所が原文から消えていると **「本文で未検出」** と表示されます。
差し戻した指摘が反映されたかの確認に使えます（この印は画面上だけで、書き出しには混ぜません）。

## インストール

パッケージ化していない拡張として読み込みます。

1. `chrome://extensions` を開く
2. 右上の **デベロッパーモード** を ON
3. **パッケージ化されていない拡張機能を読み込む** で、このディレクトリ（`redpen/`）を選ぶ
4. redpen の **詳細** を開き、**ファイルの URL へのアクセスを許可する** を ON
   （ローカルファイルをレビューするために必要）

## 使い方

### 1. 文書を開く

| 種類 | 開き方 |
|---|---|
| `.html` | Chrome でそのまま開く（`file://`） |
| `.md` | Chrome でそのまま開く。ダウンロードされてしまう場合は下記参照 |

Chrome は環境によってローカルの `.md` を表示せずダウンロードします。その場合は
ツールバーの redpen アイコンから **「.md を redpen ビューアで開く」を ON** にしてください。
以降 `file://` の `.md` は拡張内のビューアで開き、そこでレビューできます。
単発なら、ポップアップの **「ビューアで開く」** か右クリックメニューの
**「redpen ビューアで開く」** でも開けます。

Markdown はこちらでレンダリングします。左に見出しの目次（現在位置つき・折りたたみ可）、
コードブロックはシンタックスハイライトと言語ラベル付き。ライト / ダークは OS の設定に従います。

### 2. コメントを付ける

- 本文のテキストを選択 → 出てくる **✎ コメント** を押す
- または選択して **Alt+C**
- パネルの開閉は **Alt+R**

コメントは `chrome.storage.local` に保存され、同じファイルを開き直すと復元されます。

### 3. 書き出す

パネル下部の **コピー** / **.md 保存**。形式は 3 つ。

| 形式 | 中身 |
|---|---|
| 引用 + コメント（既定） | 上のサンプルの形 |
| 1 行ずつ | `- L30 — 3.2 前提条件 「本システムは常時…」 — オフライン時の挙動が未定義。` |
| JSON | 行番号・見出しパス・引用（切り詰めなし）・コメント |

## 動作範囲

- `file://` の `.md` / `.markdown` / `.mdown` / `.html` / `.htm`
- `http://localhost` / `http://127.0.0.1` 配下の同じ拡張子
- 外部のウェブサイトは対象外（意図的にそうしています）

## 仕組み

### アンカリング

コメント 1 件が覚えているのは次の 3 つです。DOM の座標は保存しません。

| 保存するもの | 用途 |
|---|---|
| 原文の行範囲 | 出力に `L30-L31` として出す。Markdown のときだけ |
| 見出しパス | 出力の位置表記。HTML のときは主軸になる |
| 引用文字列 + 前後 48 文字 | 開き直したときの貼り直し |

開き直したときは次の順で位置を探します。

1. 記録した文字オフセットに同じ引用文字列があるか
2. 無ければ本文全体から引用文字列を検索し、前後の文脈が最も一致するものを選ぶ
   （同じ語が何度も出る文書のため）
3. 空白の揺れを吸収して再検索
4. それでも無ければ **missing**（= 原文が変わった）として扱う

行番号は、markdown-it が付けたブロックの行範囲を、引用文字列の実際の位置まで絞り込んで
決めています（`anchor.js` の `refineLines`）。行の照合時は Markdown の装飾記法を落として
レンダリング後のテキストと突き合わせます。

### 構成

```
manifest.json
src/
  background.js          service worker（ショートカット・メニュー・バッジ・ビューアへの振替）
  lib/
    util.js              共通ユーティリティ、URL とドキュメントキーの判定
    store.js             chrome.storage.local の永続化レイヤ
    exporter.js          書き出し（位置 + 引用 + コメントだけを組む）
  content/
    detect.js            対象ページかどうかの判定
    markdown.js          Markdown → HTML（原文行番号を data-rp-line に焼き込む）
    outline.js           見出しの目次と現在位置
    anchor.js            選択範囲 ⇄ 保存可能なアンカー
    marks.js             コメント用 mark 要素の挿入・除去
    sidebar.js           レビューパネル（Shadow DOM）
    app.js               1 文書分のレビューセッション
    main.js              content script のエントリ
    page.css             文書側に注入するスタイル（組版・目次・ハイライト）
    hljs-theme.css       自動生成（scripts/make-hljs-theme.js）
  viewer/                拡張内ビューア（Chrome が .md を表示しない環境向け）
  popup/                 ツールバーのポップアップ
  vendor/                markdown-it (MIT), DOMPurify (Apache-2.0), highlight.js (BSD-3-Clause)
```

## 開発

```bash
npm install        # jsdom（テスト用）だけ
npm test           # ロジック / DOM / ページ全体の 3 本
npm run icons      # icons/*.png を再生成
npm run theme      # src/content/hljs-theme.css を再生成
```

`dev/preview.html` を Chrome で開くと、拡張として読み込まずに UI を確認できます
（`chrome.*` はスタブ）。「サンプルコメントを入れる」でコメントが入った状態を再現できます。

テストは 3 本立てです。

- `scripts/test.js` — 行番号の焼き込み、記法の除去、書き出しの内容と切り詰め
- `scripts/test-dom.js` — jsdom 上でのアンカー生成・再解決・ハイライト挿抜・目次
- `scripts/test-smoke.js` — `dev/preview.html` を丸ごと起動し、選択 → コメント → 保存 → 書き出しを通す
